# Comparison: GitHub Models CLI vs Promptfoo

This document compares the GitHub Models CLI evaluation approach (this PR) with the Promptfoo evaluation approach (PR #4).

## Summary

Both approaches provide automated LLM-based evaluation of agent skills, but they differ in implementation complexity, integration, and dependencies.

| Aspect | GitHub Models CLI (This PR) | Promptfoo (PR #4) |
|--------|---------------------------|------------------|
| **Dependencies** | Just `gh` CLI extension | Node.js, npm, promptfoo package (16k+ dependencies) |
| **Configuration Files** | 2 `.prompt.yml` files | `promptfooconfig.yaml`, `package.json`, `package-lock.json`, build scripts |
| **Total LOC** | ~800 (2 prompts + workflow + docs) | ~16,000+ (includes package-lock.json) |
| **CI Authentication** | Automatic via `GITHUB_TOKEN` | Requires `GITHUB_TOKEN` setup |
| **Setup Complexity** | Install `gh` extension | Install Node.js, npm dependencies, build prompts |
| **Build Step Required** | No | Yes (`npm run build:prompts`) |
| **Test Count** | 9 test cases (5 TDD + 4 Jira) | 9 test cases (5 TDD + 4 Jira) |
| **Model Provider** | GitHub Models | GitHub Models (via Promptfoo) |
| **Prompt Files** | Committed `.prompt.yml` with full skill content | Generated from build script (not committed) |
| **Evaluator Types** | LLM-rubric | LLM-rubric, string matchers, custom |
| **Result Format** | CLI output + PR comments | CLI output + HTML reports + PR comments |
| **Caching** | Not applicable | Supported |
| **Local Testing** | `gh models eval *.prompt.yml` | `npm run eval` |

## Detailed Comparison

### Dependencies and Setup

**GitHub Models CLI**
- Single dependency: `gh` CLI with `gh-models` extension
- No package managers or lockfiles
- No build step
- Total added files: 4 (2 prompts, 1 workflow, 1 doc)

**Promptfoo (PR #4)**
- Node.js and npm required
- 1,000+ npm packages installed
- 16,085 lines in `package-lock.json` alone
- Build script to generate prompts from skills
- Total added files: 12

### Workflow Complexity

**GitHub Models CLI Workflow**
```yaml
- Setup gh-models (1 command)
- Run evaluations (1 command per skill)
- Post results to PR
```

**Promptfoo Workflow**
```yaml
- Setup Node.js
- Install dependencies (npm ci)
- Build prompts from skills
- Setup cache
- Run promptfoo-action
- Post results to PR
```

### Prompt Management

**GitHub Models CLI**
- Prompts are standard `.prompt.yml` files
- Full skill content embedded directly
- Committed to repository
- Single source of truth in one file
- Easy to review in PRs

**Promptfoo**
- Prompts generated by build script
- Skill content split between `SKILL.md` and generated `prompts/*.txt`
- Generated files not committed (ephemeral)
- Requires build step to sync with skills
- More indirection between config and content

### Authentication in CI

**GitHub Models CLI**
```yaml
env:
  GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```
Just works - GitHub provides the token automatically.

**Promptfoo**
```yaml
env:
  GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```
Also works, but through Promptfoo's GitHub Models integration.

### Test Case Definitions

Both approaches use similar test structures, but the format differs:

**GitHub Models CLI**
```yaml
testData:
  - input:
      task: "User's question"
    expected: "Expected behavior"
```

**Promptfoo**
```yaml
tests:
  - description: 'Test case'
    vars:
      task: 'User question'
    assert:
      - type: llm-rubric
        value: 'Expected behavior'
```

### Evaluators

Both use LLM-rubric evaluation, but Promptfoo offers more variety:

**GitHub Models CLI**
- LLM-rubric evaluators
- String matchers (startsWith, contains, etc.)
- Similarity checks

**Promptfoo**
- All of the above, plus:
- JavaScript evaluators
- Python evaluators
- Webhook evaluators
- Custom plugins

For this use case (agent skill evaluation), the simpler LLM-rubric is sufficient.

### Results and Reporting

**GitHub Models CLI**
- CLI output shows pass/fail per test
- Results posted to PR comments
- Artifacts uploaded (text files)
- Simple, focused feedback

**Promptfoo**
- CLI output with detailed scores
- HTML report viewer
- Results posted to PR comments
- Artifacts uploaded (JSON + cache)
- More detailed analytics

### Maintainability

**GitHub Models CLI**
- Fewer moving parts
- No dependency updates needed (gh CLI is stable)
- Prompt files are self-contained
- No build process to maintain

**Promptfoo**
- More dependencies to update (npm packages)
- Build script to maintain
- Generated files to manage
- More complex workflow
- Promptfoo version pinning needed

### When to Choose Each Approach

**Choose GitHub Models CLI if you want:**
- Minimal dependencies
- Simple, straightforward setup
- Easy to understand and modify
- GitHub-native tooling
- Lower maintenance burden

**Choose Promptfoo if you want:**
- Advanced evaluator types (JS, Python, webhooks)
- Detailed HTML reports
- Response caching
- More control over evaluation process
- Existing Promptfoo expertise

## Conclusion

For evaluating agent skills in this repository, the GitHub Models CLI approach provides a simpler, more maintainable solution with fewer dependencies and lower complexity. The evaluation capabilities are sufficient for the use case (checking skill guidance quality), while the implementation is much lighter weight.

Promptfoo is a powerful tool with more features, but those features come at the cost of increased complexity and dependencies that aren't necessary for this specific use case.

## Migration Path

If you later need Promptfoo's advanced features:
1. The test cases can be easily converted (similar structure)
2. The skill content is the same
3. The evaluators translate directly

Conversely, migrating from Promptfoo to GitHub Models CLI is also straightforward (this PR demonstrates it).
