# GitHub Models CLI Evaluation Guide

This repository uses the GitHub Models CLI (`gh models`) to evaluate agent skills. This provides automated testing of skill quality using LLM-based evaluations.

## Overview

The evaluation system uses `.prompt.yml` files to test that our agent skills provide correct and helpful guidance. Each skill has a corresponding prompt file with test cases and evaluators.

## What Gets Evaluated

- **TDD Skill** (`tdd.prompt.yml`) - Tests guidance on Test-Driven Development workflow
- **Jira CLI Skill** (`jira-cli.prompt.yml`) - Tests guidance on using Jira CLI commands

## How It Works

### Prompt Files

Each `.prompt.yml` file contains:

1. **Skill Content**: The full skill instructions embedded in the system message
2. **Test Cases**: Real-world scenarios that users might ask about
3. **Evaluators**: Criteria to check if the responses are correct

Example structure:
```yaml
name: Skill Evaluation
model: openai/gpt-4o-mini
messages:
  - role: system
    content: |
      [Full skill content here]
  - role: user
    content: "{{task}}"
testData:
  - input:
      task: "User's question"
    expected: "What the response should include"
evaluators:
  - name: Check for key concept
    llm-rubric:
      rubric: The response should mention X
```

### GitHub Actions Workflow

The evaluation workflow (`.github/workflows/evaluate-skills.yml`):

1. Runs when skills or prompt files change
2. Installs the GitHub Models CLI extension
3. Evaluates each `.prompt.yml` file using `gh models eval`
4. Posts results as PR comments
5. Uploads detailed results as artifacts

## Running Evaluations Locally

### Prerequisites

1. Install the GitHub CLI: https://cli.github.com/
2. Authenticate: `gh auth login`
3. Install the models extension:
   ```bash
   gh extension install github/gh-models
   ```

### Run Evaluations

Evaluate a single skill:
```bash
gh models eval tdd.prompt.yml
gh models eval jira-cli.prompt.yml
```

Get JSON output for programmatic use:
```bash
gh models eval tdd.prompt.yml --json
```

## Understanding Results

The evaluation output shows:

- **Test case**: What scenario was tested
- **Model output**: The response generated by the skill
- **Evaluation results**: Whether each evaluator passed or failed
- **Summary**: Overall pass/fail status

Example output:
```
Test 1/5: "I need to implement a new feature..."
✓ Mentions writing tests first
✓ Includes Red-Green-Refactor cycle
✓ Provides specific actionable guidance
✓ Addresses the specific scenario

Overall: 5/5 tests passed
```

## Benefits of GitHub Models CLI

Compared to other evaluation frameworks (like Promptfoo):

1. **Native GitHub Integration**: Uses `GITHUB_TOKEN` automatically in CI
2. **No External Dependencies**: No npm packages or additional config files
3. **Simple Workflow**: Just `.prompt.yml` files and the `gh` CLI
4. **Standardized Format**: Uses GitHub's standard prompt format
5. **Built-in CI Support**: Designed for GitHub Actions workflows

## Modifying Evaluations

### Adding Test Cases

Edit the relevant `.prompt.yml` file and add to the `testData` array:

```yaml
testData:
  - input:
      task: "Your new test scenario"
    expected: "What should happen"
```

### Adding Evaluators

Add to the `evaluators` array:

```yaml
evaluators:
  - name: Descriptive name
    llm-rubric:
      rubric: The response should [criteria]
```

### Changing the Model

Update the `model` field:

```yaml
model: openai/gpt-4o-mini  # Fast and cost-effective
# or
model: openai/gpt-4.1      # More capable but slower/pricier
```

## Cost Considerations

- Each evaluation uses GitHub Models API calls
- `gpt-4o-mini` is recommended for cost-effective evaluations
- Evaluations only run when skills or prompts change
- Typical cost: < $0.01 per evaluation run

## Troubleshooting

### "Extension not found" error
```bash
gh extension install github/gh-models
```

### "Authentication failed" error
```bash
gh auth login
gh auth status
```

### Evaluation fails but should pass

1. Check the test case is clear and specific
2. Review the evaluator criteria - may be too strict
3. Try running with `--json` to see detailed scores
4. Consider adjusting the model temperature or criteria
